# 第一阶段对账合同

对照端为仓库的 v0.5.0。用随附 Python 3.12 运行复制到临时目录的 stock_research，读取复制的原始压缩快照与 latest.json。原快照编号是**解压后原始 UTF-8 字节**的 SHA-256，压缩文件另算 SHA-256。研究池以封存的 28 个代码为准。

手机默认从空库抓取 28 只 ETF 的公开原价和公司行动。测试分别覆盖直接联网路径及可选的旧快照导入路径。复权 signal_close 和 XSHG 会话用于选标的，原始 bars.close 用于估算份额。当前日可以使用同收盘日已确认的真实账户。指定历史日按原版使用空仓演示。持续跟踪另有状态和用例。

|字段|通过条件|
|---|---|
|原快照编号、输入日期、下一交易日、标的、排序、策略及路由、市场状态、状态和动作|完全相同|
|目标份额、买卖方向、现款可买、依赖卖出到账、延期份额、分单|逐项完全相同|
|收盘参考金额、佣金、印花税、过户费、滑点、费用合计、剩余现金|按原版 Decimal(str(double)) 的 ROUND_HALF_UP 逐笔计算到分，整数分完全相等|
|目标权重、动量分数、广度|绝对误差最多 1e-12，标的集合与名次仍须完全一致|
|概率、MV 权重|对应引擎移植前不发布结果。概率对账预定绝对误差 1e-9；MV 对照原交付的 1e-9，且须使用相同 SLSQP 合同|
|资料不足|区分原版的空目标、保留现金及阻断。过期行情不得生成当前操作数量|

样例包含真实快照日、历史月末、资金无法买足一手、条件买入与拒算。跟踪的月末持仓转换、保护退出和公司行动以跟踪测试单列。原版回测的权益登记、到账、拆分后可卖日需在回测账簿端另行验收。确定性策略无随机数。将来移植随机训练须固定原实验的种子、划分和输入顺序。

空库联网试验使用 2025-01-02 的复权衔接点，逐日重建信号价。2026-01-16 之前的对照用例超出新建库完整暖机范围。公开响应有各自的抓取标识。用作真实账户入口测试的现金和持仓均为测试员构造。

## 文件工作区版的实测范围

五套策略使用同一份 Python 参考输出。冻结原快照适用 54 例，联网新建库适用 41 例。桌面 Swift 的严格逐字段判定分别通过 50 例和 38 例。其余例子中 MV 的两只国债 ETF 都在 35% 上限，Windows 与测试机在线性代数计算最后几位产生差异。交换显示顺序后，逐证券比对数量、到账条件、费用和目标全部通过。严格判定保留原来的行序要求及每项差异。若行序可改变可买份额，账户建议会明确阻断。对同一组公开原文做跨日增量重建后，41 个适用用例全部逐项相符。[冻结样例](../verification/电脑对账.json) · [联网及增量样例](../verification/空库联网对账.json)

用封存行情的 2026-01-19 至 2026-11-17 区间另跑原 Python 模拟账簿，同区间的五个 Swift 账户各有 200 个交易日，共 225 笔成交。比较交易日、证券、方向、份额及当日权益到分，同时验证中断后续跑。主策略四条分支另各取一日核对。[回测证据](../verification/工作区回测对账.json)
