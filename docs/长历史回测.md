# 长历史回测与自行导入

本地开发版 0.3.0 基于 f629370。重新构建、签名，用当前安装相同的签名团队和应用标识覆盖升级。升级前可在系统「文件」另存完整的「研究工作区」。已有「设计」与活动工作区按原版本打开。移除的账户标签、自编策略以及各代数据都保存在原位置。

## 选择和使用行情

1. **手机自行采集**。进入「市场 → 回填本机历史行情」，选择已收盘的起止交易日。同一截止日也可以向前补。历史审核材料放在「研究工作区/输入/历史核验」。页面显示正在处理的证券和页末日期，支持暂停。下次选同一范围和审核版本，校验已完成页后续传。前台被终止也可用同一操作恢复。
2. **电脑直传**。在「资料 → 原始资料 → 从旧电脑导入」扫描电脑配对码。已有合法的 stock-transfer-1 包可直接传。若只有完整原生快照和来源目录，可在 Windows 上用下面的命令打包。SHA-256 使用原始 JSON 解压后的既有摘要。来源目录需包含快照内指定的全部相对路径或可唯一映射的旧绝对路径。命令输出的摘要目录可以直接交给原直传工具。
3. **查看和运行**。打开「回测」，选「导入快照」或「本机行情」，再选单个策略或全部策略。可查看当前快照编号、实际首末行情、合格样本数及连续可用区间。点起止日期打开滚轮；周末、未收盘日、倒置区间或跨越缺口均会显示原因并禁用运行。已确认的日期随该行情和工作区版本保存。

~~~powershell
py -3 tools/pack_history_import.py --snapshot 'D:\行情\快照.json' --evidence-root 'D:\行情' --expect-sha <原快照SHA256> --out 'D:\直传包'
py -3 tools/transfer.py serve --package 'D:\直传包\<清单号>'
~~~

原 advice-market-v1 快照保留解压后的原字节和编号。从 iphone-public-market-1 或 -2 生成直传包时，工具另建 advice-market-v1 外层，原快照按原编号收在 provenance 内。原电脑有完整行情目录结构时，也可使用 `tools/transfer.py pack --market-only --root <目录> --out <新目录>`。只有原价 CSV 时，还需要补齐复权信号、事件、来源和原生快照。

## 历史材料的格式

保留旧协议 stock-transfer-1、28 个完整市场代码、原交易日历和内置摘要检查。本机新行情使用 iphone-public-market-2。导入的 advice-market-v1 可携带同样的可选 history。完整样例在 `fixtures/history/public-example.zip` 的 `case/历史核验/审核.json`。

|字段|格式和含义|
|---|---|
|审核.json|含 review 和 sources。sources 把原件路径映射到 SHA-256，手机输入相对路径为 review/摘要/文件名。声明的每个文件均须存在。|
|review|schema 为 etf-history-review-1。from、through 是请求的交易日。symbols 按证券代码分组，可选 replayTarget 指定 start、end 和 strategies 数组；指定后须通过目标区间经济校验才可启用。|
|symbols 内的 listing、earliestObserved|listing 含 date 及上市公告 evidence；未知时省略。earliestObserved 是已经找到原始日线的最早交易日。|
|spans、events|spans 中每段含 from、through、evidence。evidence 指向独立的 etf-action-audit-1 JSON，含 symbol、from、through、events、sources。sources 关联该次审核所用原件，events 要和快照中的可执行事件相符。无事件区间也需说明审核范围和原件。|
|quoteSources|可列出该证券的腾讯原始未复权 day 响应。手机采集的具名分页响应自动参与核对。已核早期区间的每根真实日线逐行校验开、高、低、收和成交量。|
|gaps、issues|gaps 的键为交易日，值含 state 和 evidence。支持 BEFORE_LISTING、HALTED、NO_TRADES_CONFIRMED、SOURCE_MISSING、UNKNOWN。确认停牌、无成交和上市状态须有可定位的凭证。issues 逐项给出 symbol、date、field、reason，用于列出待核或引擎无法表达的事项。|
|priceResolutions|每个价格争议日指向 etf-price-resolution-1 记录。含 symbol、date、chosen（完整 Bar）、tencent、eastmoney（两份原始响应）、decision（独立裁定依据）及 reason。已核区间会验对证券、原价和来源。|

现金分红分别填写 record_date、date（除息）及 payment_date；cash_per_share 单位为每份现金。拆合还需 share_factor、exact_factor（十进制字符串）、rounding、available_date。share_timing 为 before_open 或经公告核定的 record_close；settlement 可为 single_account_shares。无依据的同日登记、现金替代、分托管进位或冻结权益会阻止该段回放。审核人需阅读原公告；程序负责比对原件、字段和账簿，无法替人鉴定公告内容。

## 成交、信号和范围

成交使用未复权 OHLC。分红和拆合分别进入应收现金与持仓账簿。参考价变为 (前价 − 每份现金) / 折算因子，信号尺度按 折算因子 × 前价 / (前价 − 每份现金) 更新。确认没有交易的会话只延续经过除权的估值，挂单等待下一次可交易开盘。未知缺日会中断信号连续性。

本机以 2025-01-02 的原价与信号验证旧尺度，可向前反推。恢复旧代时保留原字节。现有策略用相对价格、收益率或横截面对比，未来采用绝对价格门槛的自编策略需自行核验尺度。审核与成交均使用所选快照对应的历史；此版本没有提供历史每日的实时发布版本库。

交易起日前一个交易日已须满足样本要求。原默认 GB、MV 的 panel 需 252 个连续信号，MV 至少要 3 只；动量读第 253 个价格。上市日有凭证的证券按自己的上市历史进入样本。遇到无资料、未知停牌或未核事件时，受影响的交易日及随后的预热区间会带有证券和字段诊断。已核区间内允许策略依原规则保留现金。

前两项可在支持本工程的桌面 Swift 环境执行。后两项需要 Mac、Xcode 和已安装的 iOS 模拟器。模拟器脚本新建专用 iPhone，装入旧设计及真实样例，走正式导入接口，检查两个滚轮、确认/取消、非法日期、切源和重开。保留测试结果 History.xcresult。unsigned 产物需另行签名才能安装。Windows 电脑本次未运行模拟器、Xcode 归档、IPA 签名或真机测试。

## 回滚与文件版本

本机下载先写「数据/public-market/captures」与 candidates 断点。原响应、请求地址、抓取时间、摘要、规则/解析器版本、每次重试及拒绝原因都可查。先完成经济校验和逐件复读，再原子切换当前快照。网络故障或取消可续传；一代被拒绝后保留诊断，下次重试另建候选。

在「回填本机历史行情 → 恢复上一代本机行情」可核验并切回前版；「资料 → 已导入旧资料 → 恢复上一代导入资料」同理。市场与回测随当前选择更新。回测按行情、工作区和账簿版本分开保存，旧检查点原件留存。若需重装 v0.2，请先在新版切回可由 v0.2 打开的 v1 行情，或恢复升级前工作区备份，再以同一应用标识安装原签名版本。源码回退可在自己的本地仓库切回 f629370。
