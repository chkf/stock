# 在手机上开发股票研究台

在能访问系统文件夹的手机 agent 中选择「我的 iPhone / 股票研究台 / 研究工作区」。首次运行由 App 放入默认设计。建议 agent 先读这份说明和 workspace.json。

## 改首页

打开「设计/页面/市场.json」，拖动 blocks 数组里的对象即可重新排序。把 strength 放在 decision 前面，保存后回到 App，点任何标签页右上角的文件夹按钮，再点「重新载入工作区」。同一份行情会重新计算。未获取行情时首页可以直接联网建库。

## 新增一个完整页面和功能

「页面/行情覆盖.json」和「功能/行情覆盖.js」是一套可工作的例子。复制这两个文件，修改名称及内容，在 workspace.json 的 pages、actions 中分别加入编号和文件路径。其他页面可以放入 type 为 link、target 为页面编号的组件。tabs 数组控制底部标签的顺序，可放一至五个页面。页面的 title、tab、icon 分别控制标题、标签文字及系统图标。

页面组件可选 title、text、field、button、result、link、reload。field 的 key 会传入功能，button 与 result 的 target 对应 actions 中的同一编号。另有原生组件 strategyPicker、decision、strength、outlook、marketUpdate、quotes、replay、account、archiveLink。每个页面的 blocks 自上而下排列。可将整块行情、回测或账户作为单组件页面。

功能实现 function run(input)，返回含 title、text、rows 或 dates 与 series 的 JSON 对象。rows 每行包含字符串 label 与 value；series 每条曲线包含 name 及与 dates 等长的数值数组 values。输入包含 fields、asOf、market（证券名称、分组、日线数量）和 records。「输入/行业观察.json」成为 input.records["行业观察"]。若 fields.symbol 为完整 ETF 代码，则 input.security 包含该标的行情、复权信号价和公司行动。运行后的 JSON 在「输出/功能编号.json」，可被 agent 或其他工作区继续使用。

## 改算法

策略可在 manifest 里设置 rebalance 为 daily、weekly 或 monthly，默认按月末交易日调仓。workspace.json 的 study 控制分策略回测的初始现金、佣金费率、最低佣金、滑点费率、调仓忽略带。更改这些值会生成新的工作区版本与独立检查点。

可以用 group（分组标题放在 text）、row（横排）、stack（竖排）嵌套布局，子组件同样放在 blocks 数组。divider 绘制分隔线。

「页面/行情.json」「页面/账户.json」和「页面/回测.json」演示了如何组合行情列表、持仓、回测曲线、输入框和本机动作。command 的 target 支持 watch.add、market.refresh、study.run、job.cancel。nativeLink 可以打开账户编辑、历史账户、份额计算、报告及资料浏览。自编 JavaScript 功能通过 button 运行。

workspace.json 的 strategies 数组控制策略编号、名称、显示顺序、脚本路径和历史窗口。每套文件有独立的 run(input)，共用 library 指向的「策略/指标.js」。指标库里的样本资格、均线、强弱门槛、板块映射、动量、协方差和配置算法都可读写。原生 minimumVariance(n, matrix) 接受一维行优先协方差矩阵，以等权初值、总和为 1、单项上限 35% 运行 SLSQP。

输入有 strategy、date、dates、securities、previousState、previousSectors。每个证券的 close 是截至信号收盘且与 dates 对齐的复权价格，缺值为 null。返回 strategy、date、route、marketState、selected、weights、scores 和 breadth。protection 控制需逐日检查的 ETF，exitDrawdown 控制高点回落幅度。可添加 headline 和 rationale 自定义操作建议及理由。样例脚本显示全套返回字段。每个脚本都在手机本地独立运行，股票研究台使用原生 SwiftUI 绘制结果。新增指标或研究计算可以用 JavaScript 实现。普通功能执行有 1.5 秒及 48 MB 上限，长区间回测由本机任务按交易日推进和保存。

## 数据、版本和恢复

回测页里，绑定 replayStart、replayEnd 的 field 和 dateField 都打开上海公历日期滚轮。dateField 仅接受这两个 key。点击确认保存日期，取消返回原值。页面自动显示所选数据源、快照编号、策略可运行区间和缺日明细。旧设计可直接沿用原有 field，tabs 与自定义策略由已启用的设计决定。

从「市场 → 回填本机历史行情」选择历史起点及截止交易日。历史审核清单和原件放在「输入/历史核验」。手机也能从「资料 → 从旧电脑导入」接收完整行情包。到回测页明确选择「本机行情」或「导入快照」，重开后沿用该选择。版本差异与完整手工导入格式见源码仓库的《长历史回测》。

只会编辑文件的 agent 可以在工作区根目录写「请求.json」，下例会运行行情覆盖。支持访问此文件夹的 agent 可以独立完成「编辑设计 → 载入 → 运行 → 读结果」。

~~~json
{"id":"phone-001","operation":"run","target":"coverage","fields":{"symbol":"512800.SH"}}
~~~

App 在前台时自动读取请求，回到前台也会处理。启用刚改好的设计用 `{"id":"phone-002","operation":"reload"}`，重算策略用 `{"id":"phone-003","operation":"strategy","target":"BANK_ELSE_GB"}`。每次给出新的 id，以临时文件写完再替换「请求.json」。等「输出/请求状态.json」出现同一 id 的 done 或 error 再提交下一项。done 后读对应的功能或市场判断 JSON；error 的 message 给出原因。已完成的同一份请求在重开后会跳过。

手机上的 agent 或快捷指令还可以打开 stockresearch://workspace/reload 启用已保存的设计，或打开 stockresearch://workspace/run/coverage 运行已登记的功能。载入成功与错误详情保存在「输出/工作区状态.json」，每项功能的结果单独保存。首次使用须给手机 agent 授予此工作区的文件夹访问权。

打开 stockresearch://workspace/strategy/BANK_ELSE_GB 可切换并重算主策略。每次成功重算后，「输出/市场判断/策略编号.json」写入真实快照标识、工作区版本、信号对应的下一个交易日、是否过期、全部 ETF 排名和策略返回值。agent 可以直接读取、检验和绘图。同名输出使用原子替换。

「数据」下有 public-market（公开行情原件、快照及 current.json）、personal/accounts（已确认的账户）、reports、watchlist 和 studies。当前行情标识在 public-market/current.json，相应完整 JSON 在 snapshots。旧电脑导入包按原样保留，App 继续核对其清单。可直接读取历史快照与凭证，将衍生数据另存到「输入」，再由自定义功能处理。账户以 App 内录入的已确认版本作为真实账户。账户及数据留在本机，公开仓库随附默认设计。

「数据/原版依据/当前.json」列出实际使用的原版交易日历、公开行情与公司行动规则、Python 对照样例。每份文件在对应摘要目录内。它们用于按原口径复算并接受校验。自定义假设可复制到「输入」，用另一项研究功能运行。

保存工作文件后，明确执行「重新载入工作区」。应用会检查所有页面引用、编译脚本，并在已有行情时试算全部策略。检查失败会指出文件或原因；仍能运行上一次已启用的版本。「版本」保存每次启用时的文件与摘要。点「使用上一个已验证版本」恢复运行版本，编辑中的文件继续保留。「文件」可将整个研究工作区复制备份。恢复到同一安装前先关闭 App，将原工作区另存，再放回完整备份。卸载前应将工作区备份到该应用目录之外。
